# Raspberry Pi 3B+ 与 Switch 2 实机验收

目标为原厂 Switch 2、Pi 3B+、板载 BR/EDR 和 Ubuntu。两个 ARM Release 安装包均在 QEMU 下通过了协议、文件描述符交接及 API 集成测试。当前没有本项目在这套硬件上的实机通过记录。请在每次测试中记录系统版本、用户空间架构、BlueZ、适配器固件、游戏版本和是否发生写入。

状态用语为「已自动化测试通过」「已实机验证」「已实现但未验证」「存在兼容性问题」「尚未实现」。一项可有自动化证据和独立的实机状态。复现特定硬件故障后，附环境及抓包里程碑，将对应项改为「存在兼容性问题」。

| 功能 | 验收标准 | 当前证据 |
|---|---|---|
| 蓝牙发现 | 在 NS2 更改握法／顺序里看到 Pi 模拟的 Pro Controller | SDP、别名、DeviceID、Class 与配对窗口已实现但未验证 |
| 配对 | 新绑定，认证加密，PSM 17 与 19 来自同一主机 | 双通道 FD 交接已自动化测试通过；NS2 已实现但未验证 |
| HID | 在 NS2 的按键测试中看到 A、B、Plus 和释放 | HID 初始化与按键重放已自动化测试通过；实机待验 |
| NFC 初始化 | 游戏发出 MCU 电源、配置、状态和发现命令，进入 NFC 模式 | MCU 重放已自动化测试通过；实机待验 |
| amiibo 读取 | 在支持只读的游戏中识别正确角色；记录游戏画面和两段应答 | 合成负载重组已自动化测试通过；实机待验 |
| 动态切换 | 读取两个不同合法备份，游戏先后显示对应角色，服务持续运行 | 数据选择、移除、重新准备已实现；两枚真实标签待验 |
| 断线恢复 | 断开和重启后，原主机通过保存的绑定重新初始化 | 四轮模拟重连已自动化测试通过；板载芯片的绑定保留与重连时序待验 |
| Web | 手机操作上传、选择、准备及取消，主机事件更新页面 | 浏览器和 API 的 Simulation 已自动化测试通过；Pi LAN 待验 |
| systemd | 开机后以服务账号运行，保存的主机可恢复，普通服务没有网络管理能力 | unit 与安装流程已实现但未验证 |
| 安全恢复 | 记录原属性，分别正常停止、强制终止 helper 和重启，核对原属性及系统蓝牙设备 | 租约、恢复日志及 ExecStopPost 已实现但未验证 |
| 新格式、写入、所有者注册 | 拒绝未支持请求，原文件不被改写 | 写入与注册尚未实现；Unsupported 路径已自动化测试通过 |

## Pi 上的执行顺序

1. 运行 `sudo /usr/local/libexec/amiibo-pi/amiibo-bt diagnose`，保存 `bluetoothctl show` 和 `systemctl cat bluetooth`。按 README 安装并读取本地令牌。
2. 先验证发现、两条通道和主机按键测试，再开始 NFC 验收。没有手柄就绪时网页会拒绝准备标签。
3. 用已知可在同一游戏正常读取的传统备份，记录 Armed、Discovered、Reading、Transferred 和游戏结果。快速连续状态可能被 WebSocket 合并；详细证据使用本地 btmon。记录第二个标签和取消操作的结果。
4. 显式断开、手动重连；再测试主机休眠、唤醒和 Pi 重启后的恢复。比较地址与绑定是否一致，记录第一次失败的通道和主机响应。
5. 在保留 SSH 连接的测试时段执行正常停止。再次配对后执行 `sudo systemctl kill --signal=SIGKILL --kill-who=main amiibo-bt`，检查 journal、bluetooth.service、原适配器属性和其他蓝牙设备。手动恢复命令见[运行手册](bluetooth.md)。
6. 只有主机反馈满足该行的验收标准，才标记「已实机验证」。
